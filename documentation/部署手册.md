# Nebular Design · 部署手册

> 从「只在你电脑上跑」到「有网址、别人能用」。
> 方案 A：Vercel（前端）+ Fly.io（后端）+ Neon（数据库）+ Cloudflare R2（存储）。不买域名。
> 目标：**每月 ≤ $10**。实际预计 **$1–2**。

**顺序不能乱**，因为后一步要用前一步产生的值：

```
① Neon 数据库 ──┐
② R2 存储    ──┼──> ③ Fly 后端 ──> ④ Vercel 前端 ──> ⑤ 回填 CORS
                │         ↑                              │
                └─────────┴──────────────────────────────┘
                    （前端地址要回填给后端，所以最后有一步回头）
```

---

## 术语先说清

| 词 | 是什么 | 这里指 |
| --- | --- | --- |
| **环境变量** | 不写进代码、启动时才注入的配置 | 数据库地址、API key |
| **Secret** | 加密存储的环境变量，平台不给你再看第二眼 | Fly 上的 `fly secrets set` |
| **CORS** | 浏览器的同源保护。后端要显式声明「我允许这个网址来调我」 | `FRONTEND_URL` |
| **冷启动** | 机器停了，下一个访客要等它开机 | 见 `待办清单.md` A2 |
| **scale-to-zero** | 没人用就停机 | 省钱的关键，$11/月 → $1/月 |

## ① Neon —— Postgres 数据库

**https://neon.tech** → Sign Up → Continue with GitHub。**不要信用卡。**

建 project：

| 字段 | 填 |
| --- | --- |
| Project name | `nebular` |
| Postgres version | 默认最新即可 |
| Cloud / Region | **AWS · US East (Ohio) us-east-2** ← 实际用的这个 |

> Region 要和第 ③ 步的 Fly region 对上。一次请求要往数据库跑好几个来回，
> 两边放在不同海岸增加的延迟，比代码里任何优化省下来的都多。
> us-east-2 是俄亥俄，Fly 没有俄亥俄，最近的是 `ord`（芝加哥，约 10 ms），
> `fly.toml` 已经设成这个。

建完复制 **Connection string**：

```
postgresql://neondb_owner:xxxx@ep-xxx.us-east-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
```

> **已经处理好的坑**：`sslmode` 和 `channel_binding` 是 libpq 的写法，
> 本项目用的 asyncpg 不认识，原样传过去会在启动时抛
> `TypeError: connect() got an unexpected keyword argument 'sslmode'` —— 容器起不来，
> 而且报错指向 SQLAlchemy，完全看不出是这串 URL 的问题。
> `config.py` 的 `async_database_url` 现在会自动翻译成 `?ssl=require`，
> **已经拿真的 Neon 实例连通验证过**（PostgreSQL 18.4）。整串原样粘贴即可。

> 🔑 **这串密码贴进过对话，部署跑通后必须换掉。**
> 换法和完整的凭据轮换清单在 [`待办清单.md` → F1](待办清单.md)。

**免费档**：0.5 GB 存储。`ldraw` 搬走之后一个 build 约 31 KB → **约 16000 个**。

## ② Cloudflare R2 —— 图片和模型存储

**https://dash.cloudflare.com/sign-up** → 验证邮箱 → 左侧 **R2 Object Storage** → Enable。

⚠️ **要绑卡**。免费额度：10 GB 存储、100 万次写、1000 万次读，**出站流量不要钱**。

> 为什么不用 S3：代码是同一套（R2 兼容 S3 API，boto3 换个 endpoint 就行）。
> 区别在账单——S3 每传给浏览器 1 GB 收 $0.09，而这里存的每一个对象都是要传给浏览器的。
> R2 出站 $0。

1. **Create bucket** → 名字 `nebular-uploads` → Location **Automatic**
2. R2 首页 → **Manage R2 API Tokens** → **Create API Token**
   - Permissions: **Object Read & Write**
   - Specify bucket: `nebular-uploads`
3. 记下三样（**Secret 只显示这一次**）：

| 名字 | 样子 | 对应环境变量 |
| --- | --- | --- |
| Access Key ID | 32 位十六进制 | `AWS_ACCESS_KEY_ID` |
| Secret Access Key | 64 位十六进制 | `AWS_SECRET_ACCESS_KEY` |
| Endpoint | `https://<account-id>.r2.cloudflarestorage.com` | `S3_ENDPOINT_URL` |

> Endpoint **不含 bucket 名**。加上去的话 boto3 会拼成
> `.../nebular-uploads/nebular-uploads/images/xxx.jpg`，然后 404。

## ③ Fly.io —— 后端

**https://fly.io/app/sign-up**（要绑卡）。装 CLI：

```bash
brew install flyctl          # 或者 curl -L https://fly.io/install.sh | sh
fly auth login               # 会开浏览器
```

`backend/fly.toml` 已经写好了（2 GB 机型、scale-to-zero、区域 iad）。

```bash
cd backend

# app 名字全球唯一，被占了就换一个，同时改 fly.toml 里的 app =
fly apps create nebular-design-api

# 全部密钥一次性设进去（这一行不要提交进 git）
fly secrets set \
  DATABASE_URL='<第①步整串>' \
  SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')" \
  ANTHROPIC_API_KEY='<你的 key>' \
  AWS_ACCESS_KEY_ID='<第②步>' \
  AWS_SECRET_ACCESS_KEY='<第②步>' \
  S3_ENDPOINT_URL='<第②步 endpoint>' \
  S3_BUCKET_NAME='nebular-uploads' \
  FRONTEND_URL='https://placeholder.vercel.app'

fly deploy                   # 第一次约 5–10 分钟：要传 1.4 GB 镜像
```

> `FRONTEND_URL` 先填占位符，第 ⑤ 步再改成真的。
> 后端启动时若发现 `SECRET_KEY` 还是仓库里那个占位符，会**直接拒绝启动**——
> 这是故意的，一个已知密钥签出来的 JWT 谁都能伪造，而警告日志会被滚过去。

验证：

```bash
fly status
curl https://nebular-design-api.fly.dev/health     # {"status":"ok",...}
fly logs                                            # 出问题看这里
```

## ④ Vercel —— 前端

**https://vercel.com/signup** → GitHub 登录 → **Add New → Project** → 选 `nebular-design` 仓库。

| 设置 | 填 |
| --- | --- |
| Framework Preset | Next.js（自动识别） |
| **Root Directory** | **`nebular-design`** ← 必改，仓库根目录不是前端 |
| Environment Variables | `NEXT_PUBLIC_API_URL` = `https://nebular-design-api.fly.dev` |

**Deploy**。

> ⚠️ `NEXT_PUBLIC_*` 是**构建时**烤进 JS 包里的，不是运行时读的。
> 改了这个值必须**重新部署**才生效，光重启没用。

部署完拿到网址，形如 `https://nebular-design.vercel.app`。

## ⑤ 回填 CORS

后端现在还不认识前端的网址，浏览器会拦下每一个请求，
控制台里只显示一句没头没尾的 `Failed to fetch`。

```bash
cd backend
fly secrets set FRONTEND_URL='https://nebular-design.vercel.app'
# 改 secret 会自动重启机器，不需要重新 deploy
```

> Vercel 每个 PR 还会生成一个 preview 网址（`nebular-design-git-xxx.vercel.app`），
> 那些**不在**允许列表里，用它们访问会被 CORS 挡掉。要用就一起加进来，逗号分隔。

## ⑥ 验收清单

打开 Vercel 网址，依次确认：

- [ ] 首页能打开（**第一次会慢 3–10 秒**，后端在冷启动）
- [ ] 注册一个账号 → 成功
- [ ] 传一张建筑照片 → 出结果（**首次约 30–60 秒**，模型第一次载入内存）
- [ ] 3D 模型显示出来（这一步会单独请求 `/api/images/{id}/ldraw`）
- [ ] Download .ldr 能下
- [ ] 照片和渲染图都能显示（能显示 = R2 presign 对了）
- [ ] Profile 里点卡片能进详情页
- [ ] 退出登录再进，历史还在
- [ ] 聊天室能发消息（**注意 A2：闲置一会儿连接会断**）

全绿之后**立刻**做一件事：**轮换 Neon 密码和 R2 密钥**（[`待办清单.md` → F1](待办清单.md)）。
放到验收之后是因为换早了会打断部署；但也就到此为止，别再往后拖。

| 项 | 计费 | 预计 |
| --- | --- | --- |

| Fly 出站流量 | 前 100 GB 免费 | $0 |
| Neon | 免费档 | $0 |
| R2 | 10 GB + 免费出站 | $0 |
| Vercel | Hobby | $0 |
| Anthropic API | **实测 1.22 美分/次**（见下） | **按用量** |
| | | **合计 < $5** |

### Anthropic 具体怎么算的

按 token 计费，输入和输出分开定价。用 Tower Bridge 那张真实照片实测：

| | token | 优惠价 $2/$10 per 1M | 原价 $3/$15 |
| --- | ---: | ---: | ---: |
| 输入 | 2257（图片 1737 + 文字 520） | $0.0045 | $0.0068 |
| 输出 | 772 | $0.0077 | $0.0116 |
| **单次** | | **≈ 1.22 美分** | **≈ 1.84 美分** |

- Sonnet 5 优惠价到 **2026-08-31**，之后回 $3/$15
- **$10 ≈ 800 次分析**（优惠期后约 540 次）
- **只有 `/api/images/upload` 会调它，一次**。登录 / 聊天 / 看历史 / 看 3D / 下载 .ldr 都不花钱
- Claude 只做起名 + 写描述 + 步骤标题。候选搜索、深度、分割、配色、几何、零件清单全在自己服务器上算
- 输入里 77% 是图片，所以 `bricks.py` 先把长边缩到 1568px（实测压掉 90% 体积）

⚠️ **唯一会失控的是 Anthropic**。别的三家超了免费额度就是限流或停服，
Anthropic 没有天花板，会一直扣。去 **console.anthropic.com → Settings → Limits** 设月度上限。
后端有限流，但那是按 IP 的；真有人拿一堆 IP 刷上传接口，最后挡住他的是这个金额上限。

**看账单**：`fly dashboard` / Neon 和 Cloudflare 后台。

## ⑧ 出问题怎么查

| 症状 | 先看哪 | 常见原因 |
| --- | --- | --- |
| 网站打不开 | `fly logs` | 启动就崩，多半是某个 secret 没设或格式错 |
| `Refusing to start in production` | `fly logs` | `SECRET_KEY` 是占位符 / 太短，或 `FRONTEND_URL` 是 `http://` |
| 前端一片空白，控制台 `Failed to fetch` | 浏览器 Network 面板 | CORS，第 ⑤ 步没做或网址拼错 |
| 图片全是破图 | Network 里点那个图片 URL | R2 presign 失败，多半 `S3_ENDPOINT_URL` 带了 bucket 名 |
| 3D 区域一直转圈 | Network 看 `/ldraw` 那个请求 | 对象没写进 R2，或者 key 丢了 |
| 上传转很久然后 500 | `fly logs` 找 OOM | 内存不够，机器被 kill。确认是 2 GB |
| 每次第一下都很慢 | 正常 | 冷启动。要治只能加钱常开，或做 D3 把模型搬去浏览器 |

**回滚**：`fly releases` 看版本，`fly deploy --image <上一版镜像>`。
Vercel 在后台点上一次部署的 **Promote to Production**。

## ⑨ 之后每次改代码怎么上线

```bash
# 前端：推到 main，Vercel 自动部署
git push

# 后端：手动
cd backend && fly deploy
```

没有 CI。要做的话是 GitHub Actions 加一个 `fly deploy --remote-only`，
但在只有你一个人推代码的阶段，多这一层只是多一个会坏的东西。
