## A. 本次明确决定「先不做」

### A1 ⚪ 发信功能（密码重置 / 邮箱验证）

**现状**：完全没有。用户忘记密码 = 账号找不回来，只能你手动进数据库改。

**为什么不做**：需要一个外部发信服务（Resend 免费档 3000 封/月，或 SendGrid、Postmark）。
你说这一块暂时不考虑。

**什么时候必须做**：只要有第二个真实用户注册，就会有人忘密码。
自用 / 给朋友看阶段不需要。

**工作量**：注册 Resend 拿 API key（10 分钟）+ 后端两个接口 + 一个前端页面 ≈ 半天。
数据库要加一张 `password_reset_tokens` 表（token 哈希、过期时间、是否已用）。

**注意**：重置 token 必须**存哈希**，和密码一个道理；必须**单次使用**；有效期 30 分钟以内。

---

### A2 ⚪ 聊天室冷启动

**现状**：后端用 Fly.io 的 scale-to-zero（没人访问就停机，省钱到约 $1/月）。
但**停机会切断所有 WebSocket 连接**。

**表现**：聊天室开着放几分钟 → 后端停机 → 连接断开 → 页面上聊天就死了，刷新才恢复；
再进来第一条消息要等 3–10 秒冷启动。

**为什么不做**：治本的办法有两个，都很贵：
1. 关掉 scale-to-zero，机器常开 → 每月约 $11（2GB 机型），超出你 $10 的预算
2. 聊天单独搬到 Cloudflare Durable Objects → 免费，但是一次重写

你选择接受冷启动。

**什么时候必须做**：真的有人在这个聊天室里聊天的时候。现在没有。

**缓解（成本为 0，属于 A3 的一部分）**：客户端自动重连，用户就只感觉「卡了一下」而不是「坏了」。

## B. 聊天室专业化清单

现在的实现：内存里一个 `ConnectionManager` + Postgres 存历史 + 裸 WebSocket。
能跑，但不是「专业」的样子。按性价比排序：

| # | 项 | 优先级 | 说明 | 工作量 |
| --- | --- | --- | --- | --- |
| B1 | **客户端自动重连**（指数退避 + jitter） | 🟠 | 断了 1s、2s、4s、8s…重试，每次加随机抖动避免所有人同时重连打垮服务器。**这是缓解 A2 的关键一条** | 30 行前端 |
| B2 | **消息 ID + 去重** | 🟠 | 重连后要重放漏掉的消息，没有 ID 就会重复刷屏 | 后端已有 `Message.id`，前端加个 Set |
| B3 | **游标分页历史** | 🟡 | 现在是 `limit=50` 取最新的。消息多了以后没法往上翻 | 后端加 `before_id` 参数 |
| B4 | **心跳 / ping-pong** | 🟡 | 检测「连接还在但对端已经死了」的僵尸连接 | 20 行 |
| B5 | **Redis pub/sub 广播** | ⚪ | 单实例不需要。**扩到 2 个实例那天，A 实例的消息传不到 B 实例的用户** | 半天 + Redis 账号 |
| B6 | **搬到 Cloudflare Durable Objects** | ⚪ | 业界针对这个场景的标准答案，免费档够用，不受 scale-to-zero 影响 | 重写，2–3 天 |

✅ **已完成**：服务端分配游客身份（防冒充）、服务端限流、修掉历史消息的 N+1 查询（61 次 → 1 次）。

### F1 🔴 轮换在对话/截图里出现过的凭据

**必须做的时间点**：网站部署跑通、确认能用之后，立刻做。不要拖到"以后有空"。

**为什么**：凭据一旦离开你自己的机器，就当它已经泄露了。不是说现在有人在盯着你——是因为
聊天记录、截图、剪贴板历史、云同步的临时文件，这些东西存在的地方比你以为的多，
而且**你永远不会收到"它被复制走了"的通知**。轮换的成本是三分钟，不轮换的代价是别人拿到
你数据库的完整读写权。

**要换哪些**（凡是**贴进过对话、截图、或者截图里能看见的**，都算）：

| 凭据 | 泄露方式 | 怎么换 |
| --- | --- | --- |
| **Neon 数据库密码** | 2026-08-06 完整连接串贴进了对话 | Neon 后台 → 项目 → Connection Details → **Reset password** → 拿新串 `fly secrets set DATABASE_URL='<新串>'` |
| **R2 Access Key / Secret** | 建完就要贴给我配置 | Cloudflare R2 → Manage API tokens → 删旧 token → 新建 → `fly secrets set AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=...` |

**不需要换的**：
- `SECRET_KEY` —— 部署时由 `fly secrets set` 里的 `python3 -c 'secrets.token_urlsafe(48)'`
  **当场生成**，从没有被完整打印过
- `ANTHROPIC_API_KEY` —— 一直在 `.env` 里，没进过对话正文。
  但它是唯一真花钱的东西，**去后台设个月度上限**比换 key 更要紧

**换完怎么确认生效**：`fly secrets set` 会自动重启机器。
`fly logs` 看到 `Application startup complete` + 网站还能登录 = 成了。
旧密码此刻已经作废——如果网站坏了，说明有地方还在用旧的，往回查。

> 一般规律：**任何走过屏幕的密钥都要换。** 这不是这个项目特有的，是所有项目的默认动作。
> 真正的做法是密钥永远只在 `fly secrets set` / `.env` 和你的密码管理器之间流动，
> 不进聊天、不进 issue、不进截图。
